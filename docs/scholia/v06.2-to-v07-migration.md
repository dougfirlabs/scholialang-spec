# Migration: Scholia v0.6.2 → v0.7 (PROPOSED)

**Status:** proposed candidate — describes the additive Map/Event/Task
grammar 0.7.0 / package 0.7.3 proposal in
`docs/scholia/SCHOLIA_v0.7_SPEC.md`. Until that proposal is accepted,
v0.6.2 remains canonical and nothing in this note is in force.

## What changes

- **Three new atom kinds** — `<Map>`, `<Event>`, `<Task>` — join the
  closed catalog (32 → 35). Their contracts live in §§3–6 of the
  proposed spec. All three require a kind-prefixed trace-local `id`,
  reject unknown fields and nested children, and never execute work,
  deliver notifications, or grant authority.
- **Grammar axis bumps to 0.7.0.** A grown closed catalog is a grammar
  change; describing it as the unchanged 0.6.2 grammar would be
  misleading. The package/validator axis moves to 0.7.3 separately.
- **New validator rule codes** (`semantic_*`, `map_*`, `event_*`,
  `task_*`, `grammar_profile_unsupported`) are proposed in §9 of the
  new spec; legacy rules keep their names and behavior.
- **A current catalog projection** is added at
  `reference/v0.7/atoms_index.yaml` with a generated
  `reference/v0.7/notation-reference.md`. The legacy projection
  `reference/atoms_index.yaml` is preserved unchanged. The current
  projection also repairs three documentation gaps for fields that
  already exist in implementation 0.7.2 (`Observation.fingerprint`;
  the `on` attribute of `Uncertainty` and `Confidence`, which the
  legacy YAML encoded as an unquoted scalar that loads as boolean
  true). These are documentation parity repairs, not new semantics.

## What does not change

- Every valid v0.6.2 (and earlier) trace remains valid, byte-for-byte,
  with unchanged canonical identities. No historical trace is
  rewritten.
- `<EventRef>` is unchanged and coexists with `<Event>`: EventRef
  remains the reference to an externally recorded event; Event records
  an occurrence in the trace. An EventRef may point at an Event via
  its existing `for` relationship; no automatic reinterpretation is
  added.
- The inline `MAP` primitive operator is unchanged and distinct from
  the `<Map>` atom.
- Canonical hashing, stable local IDs, provenance exclusions, the DAG
  registry, the lazy prelude, and the `fingerprint=` revision are
  unchanged.

## For emitters

Emit the new kinds only after the proposal is accepted and a consumer
advertising grammar 0.7.0 is on the other side. The new kinds require:
a kind-prefixed `id` (`Map_…` / `Event_…` / `Task_…`), the per-kind
required fields (§§4–6), and — for `<Task status="satisfied|unsatisfied">`
— an `evidence_ref` naming the supporting atom. A satisfied `<Task>`
does not close a required `<Goal>`; existing closure rules are
unchanged.

## For consumers and adapters

- A 0.7-conforming consumer accepts legacy traces unchanged and
  provides an explicit grammar-profile entry point: new kinds under a
  selected legacy 0.6.2 profile produce a structured
  `grammar_profile_unsupported` diagnostic, as does an unknown future
  profile.
- An already-released 0.7.2 consumer fails to parse the new kinds;
  that observed unknown-kind failure is the fallback. Adapters must
  negotiate the advertised kind/grammar contract first and surface
  unsupported capability/version — never down-convert `Map` to
  `Storing`, `Event` to `EventRef`, or `Task` to `Action`.
- Rollback: retain prior spec/implementation refs and artifact hashes;
  do not assume old software can read new kinds.

## Conformance

The shared fixture matrix for this proposal is
`conformance/v0.7/semantic_atoms.json` (registered append-only in
`compatibility-manifest.json`). Implementations claiming the proposed
contract execute every case; runtime-only obligations (forced
canonical collisions, no-side-effect probes, old-artifact probes) are
declared in the suite metadata for the implementing consumer's own
test suite.
